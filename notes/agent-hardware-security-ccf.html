智能体硬件创新与安全：当 AI 有了手脚，谁保证安全

宋继强、谭晓生、吴向斌　·　2026-11-09　·　摘要约 753 字　·　阅读原文 ↗

以前防大模型「说错话」，现在要防智能体「做错事」；随之而来的是「第三种身份」和迁回 CPU 的系统瓶颈。硬件能兜住的，是整条因果链的可信。

核心要点

  • 从说错话到做错事：这一代智能体能操纵硬件，已出现删邮件、删库；机器人安全水位极低（某上市机器人公司全公司只有一名安全人员）。2025-10-24 上海活动上，一句话即让机器人冲上台打模特、破四足机器狗与无人机——攻击面就是自然语言交互界面。
  • 第三种身份：人的身份、应用身份之后，Agent 身份及其权限与访问控制是全新问题。
  • 数据安全的老办法失效：库/表/行/列级 ACL 不适用——不让模型知道它就是个傻子，让它知道又要管住「什么情况下该用什么数据」。
  • 根因：内容与指令同源，类似冯·诺依曼结构里指令与数据同源，Prompt 注入无法根除；沙箱本身也会被逃逸。
  • 硬件瓶颈迁移：Agent 循环要任务编排、调工具、写状态、形成记忆、多智能体通信，任务时长从十几秒拉到数小时；CPU 回到中心，且 CPU / GPU / 内存都缺。
  • 硬件防线：可信根（不可篡改）、硬件隔离（Intel TDX）等，目标是让整条因果链可信，而不是逐点打补丁。
  • 落地节奏：汽车最谨慎（出事就是人命，视觉大模型还没交给智能体）；智能家居（Home Assistant、小米 MiClaw）已在渗透；智能仓储在用。

值得记住的结论

Agent 安全的落点是「身份 + 权限 + 可审计的执行链」，不是内容过滤。想上生产，先回答三个问题：这个动作是谁授权的、在哪一层被拦住、事后能不能复原因果链。
