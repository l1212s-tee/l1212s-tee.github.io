NeurIPS 2026｜AI 搜索搜到的图为什么用不了：港科大的图像编号与 ODE

机器之心　·　2026-11-15　·　摘要约 1400 字　·　阅读原文 ↗

瓶颈不在「搜得到」，而在「搜回的图能不能被下一步接住」。给每张图编号、让工具接力用同一张图；再用 ODE 按解题记录改出题规则。

问题：图看得见，但交不出去

示例链条：雪山照片 → 裁出山脊 → 以图搜图找到「折多山」→ 查网页 → 把搜到的另一张照片放大核对 → 锁定垭口。卡点在最后那次放大：多数多模态搜索系统里，模型能看见刚搜回的照片，却没法把这张图交给下一个工具。

方案一：视觉原生智能体框架

  • 支持九种工具：检索网页/论文/图片、打开来源页、放大、旋转、用 Python 计算
  • 题目原图与工具返回的新图都存进同一个 image bank，每张图有独立编号
  • 任何工具都能按编号接着用同一张图——这就是「接得住」

方案二：ODE（On-policy Data Evolution）

  • 一次「搜索 → 调工具 → 给答案」全过程称为一次 rollout
  • 出题器先找至少两个独立来源能核实的对象，挑有细节（图例/数字/标记）的图，组织成证据图，再从中选相连线索编题并删掉泄漏答案的提示
  • 每轮出 32 道题，目标模型逐题 rollout（参数不变）；分析器对照解题记录诊断，通过审核的改动写进下一轮规则
  • 最多演化 五轮；RL 题用目标模型跑，SFT 示范用教师模型 GPT-5.2 跑；规则可撤回

案例：1948 年联合国地图题，模型漏数托管领土、把西南非洲算进去；正确答案是图上 10 个 / 初始 11 个 ≈ 91%。分析器据此要求数量线索逐项以图搜图核实、视觉操作上限 4→5 步、带图线索占比 50%→40%；到巴尔的摩港航道图又因「题太难」把占比回调到 50%。

关键数字

  • 8B 八项均分 24.9% → 39.0%；30B 30.6% → 41.5%
  • Qwen3-VL-30B 拆解：标准流程 24.8% → 换框架 30.6% → +SFT 39.5% → +RL 41.5%
  • MMSearch（8B）：47.3% → 61.7% → 66.0%
  • 商业模型同框架：Gemini 2.5 Flash 32.0%→35.55%；Pro 37.9%→42.21%；GPT-5 七项全升，均分 44.41%
  • ODE-30B-A3B-RL 41.53%，与 Gemini 2.5 Pro 仅差 0.68pp
  • 图像复用（MMBC）：约四成题目用到旧图；关闭复用 7.59% → 全保留 12.50%；306 次复用中 191 次放大、113 次以图搜图
  • 等量对照（各 2,000 条 SFT）：含 ≥4 张工具图的示范 10.5% → 42.9%；含图像操作+搜索 35.3% → 54.8%
  • 等量对照（各 4,000 题 RL）：MMBC 上 8.5%（SFT 后）→ 固定规则 5.8% → ODE 12.5%
  • 工具调用形态：SFT 教师 15.94→12.19 次、返回图 1.25→3.75 张；8B 做 RL 题 6.14→15.33 次、图 3.07→11.00 张

值得记住的结论

  • 多模态搜索的下一道门槛是上下文接力：图片要有稳定标识，才能被后续工具复用
  • 数据合成不只调「题量」，要按 rollout 诊断调「出题规则」，而且要能撤回改错的规则
  • 训练出的 30B（41.53%）已逼近 Gemini 2.5 Pro（42.21%）——框架与数据的工程收益，可以部分替代模型规模
