AI 搜索是怎么做出来的

金色传说大聪明　·　2026-10-21　·　摘要约 1100 字　·　阅读原文 ↗

模型只做两件事：决定搜什么、决定怎么用搜回来的东西。真假、时效、延迟，全落在搜索这一侧。

机制：一次「来回」

  • 模型发现靠自己答不了 → 写一段格式固定的检索请求（搜什么、要几条）→ 外部程序认出来去检索 → 十条结果原样贴回上下文 → 模型接着写。
  • 用户看到的一句「明天晴，不用带伞，出处：北京日报」，背后就是这一趟来回。
  • 读者换了三次：人读（给链接）→ 模型读（替你总结）→ Agent 读（拆子问题、一轮轮搜）。

四件被 Agent 逼出来的事

一、听懂检索词

  • 搜索给 Agent 每条结果的权威等级、发布时间、排序满意度；Agent 回传最终引用了哪几条、思考过程、答案打分（answer reward），搜索拿去改排序。
  • WorkBuddy 联合评测：单任务平均调用搜索 8 次 → 5 次；有开发者说以前翻 20 个网页，现在 5 个够。
  • 排序模型：Label 模型打标 → 大尺寸 Teacher → 蒸馏成 Student 上线；样本从线上「结果不满意」的检索词里挖，交智能体标注后增量训练，迭代从按月变按天。

二、分辨真假

  • 收录那一刻就用大模型打分，三级：站点、账号、页面——作者是谁、历史发过什么、内容有无出处。
  • 对 AIGC 水文与 GEO（专门写给 AI 引用的内容）是攻防：单篇用识别模型打，批量账号按发布规律专项识别。
  • 设了反爬的站点因尊重版权不收录；携程这类打不开的走三方合作。

三、补上新信息

  • 财经/股票类站点约一小时刷一次。
  • 比网页更快的股价、天气、航班走独立插件系统（类比谷歌 OneBox、百度「阿拉丁」），接 13 个垂直行业、157 个头部信源（腾讯自选股、飞常准、携程、京东），返回结构化卡片，中文带字段名和更新时间，模型拿到直接用。

四、压低延迟

  • 单次 300ms 以内返回（升级前 400–500ms），连搜三轮不到一秒。
  • 索引：倒排 + 向量合成一张千亿规模索引，召回率 94%+，平均检索 8ms。
  • 排序：Gist Token——建索引时把每个网页压成 100 个 token 存进 KV Cache，查询时只算检索词那十几个 token，计算量只跟检索词长度有关，省约 30% 在线推理成本。
  • 推理：一套框架跑多种卡型，单位推理成本降 90%。

搜索变成 API / MCP

  • 腾讯云获取，标准版按量后付费 20 元/千次（一次两分钱）；每月 2000 次免费（10/10–11/30 用激活码可提到 6000 次）。
  • 只返回条目：passage/content 是原文摘录，最长约 800 / 2500 字，答案由模型自己写。Cnt 最多 50 条，可限定站点、时间范围、垂直领域（财经/新闻/党政/学术）；插件卡片与动态摘要要标准版起，权威度评分（0–5）要旗舰版。
  • 写法三代：ChatGPT Plugin 的 yaml → Function Calling → MCP，本质都是「写给模型看的说明书」。MCP 走 initialize → tools/list → tools/call，结果与 API 完全相同，只多那份说明书。

多跳的分工

问「2026 年诺贝尔物理学奖得主里最年轻的那位在哪所大学、现任校长是谁」，Codex 发了 6 次 tools/call，主干三跳；同一句话丢给 API 单次搜索，只回来 10 条「哈尔岑获奖」新闻，大学和校长一条都没有。

原因：第二跳该搜什么，要等第一跳读完才知道。规划只能 Agent 做，搜索只负责把每一跳搜准搜快。

值得记住的结论

给 Agent 挑搜索，照这四条看：

  1. 权威来源：财报、政策、医疗是不是官方口径
  2. 实时结构化卡片：股价、天气这类
  3. 单次是否几百毫秒，连搜几轮不卡
  4. 能否限定站点、时间、领域，让 Agent 自己收窄

价格参照：2023 年底行业普遍 15–25 美元/千次（非 AI 搜索 5 美元/千次），现在已到 20 元/千次量级。
